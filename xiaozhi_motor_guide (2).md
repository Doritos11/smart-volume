# Xiaozhi + голосовое управление мотором (ESP32-S3)

Полная инструкция: от установки ESP-IDF до фразы "включи мотор", которая реально понимается через LLM.

---

## 0. Проверь/поправь распиновку

Твоё железо (ESP32-S3, INMP441, MAX98357A, 1.54" ST7789) — это ровно референсный комплект проекта Xiaozhi под сборку **"Bread Compact WiFi + LCD"**. Официальная (проверенная) распиновка:

**Микрофон INMP441:**
| ESP32-S3 | INMP441 |
|---|---|
| GPIO4 | WS |
| GPIO5 | SCK |
| GPIO6 | SD |
| 3V3 | VDD |
| GND | GND + L/R (перемычкой) |

**Усилитель MAX98357A:**
| ESP32-S3 | MAX98357A |
|---|---|
| GPIO7 | DIN |
| GPIO15 | BCLK |
| GPIO16 | LRC |
| 3V3 | VIN + SD (перемычкой) |
| GND | GND + GAIN (перемычкой) |

**Дисплей ST7789 1.54":**
| ESP32-S3 | Дисплей |
|---|---|
| GPIO21 | SCL |
| GPIO47 | SDA |
| GPIO45 | RST |
| GPIO40 | DC |
| GPIO41 | CS |
| GPIO42 | BL |
| 3V3 | VCC |
| GND | GND |

Если у тебя провода идут на другие GPIO — либо перепаяй/перекинь под эту таблицу (тогда ничего в коде менять не надо), либо позже поправишь `config.h` под свои пины (см. шаг 5). Проще перевесить провода — так гарантированно заработает с первого раза.

**Мотор** — используем два GPIO, например **GPIO2** и **GPIO3**. Логика: когда мотор включаем — на первый пин LOW, на второй HIGH; когда выключаем — наоборот (первый HIGH, второй LOW). Это стандартная схема для модуля реле на 2 канала или драйвера типа L298N/L9110 (два входа IN1/IN2 — таким сигналом задаётся и включение, и направление). ВАЖНО: сигнал с GPIO идёт не на мотор напрямую, а на модуль реле/драйвера — мотор запитан отдельно, от своего источника питания, не от ESP32.

## 1. Установка ESP-IDF (через официальный инсталлятor, без VS Code мастера)

VS Code-расширение косячит с мастером настройки — ставим напрямую с сайта Espressif, это даже надёжнее.

1. Открой в браузере: **https://dl.espressif.com/dl/esp-idf/**
2. Увидишь список версий и ссылку **"Windows Installer"** — жми на неё, попадёшь на страницу с файлами для скачивания
3. Там будет несколько `.exe` файлов с разными версиями ESP-IDF (v5.1, v5.3, v5.5 и т.д.) — скачай тот, что с **v5.5** (или любой v5.x, если 5.5 нет)
4. Запусти скачанный `.exe`
5. В установщике:
   - Соглашаешься с лицензией → Next
   - **Destination folder** — укажи что-то простое, например `C:\esp-idf`. **Важно:** без кириллицы и пробелов в пути, иначе сборка потом упадёт с ошибками
   - На вопросе про компоненты — оставь всё по умолчанию (он сам скачает Python, Git, компилятор для ESP32)
   - Жми Install и жди — качает несколько гигабайт, может занять 20-40 минут в зависимости от интернета
6. По окончании установки на рабочем столе появится ярлык вида **"ESP-IDF 5.5 CMD"** (или PowerShell)
7. Открой этот ярлык — откроется чёрное окно терминала. Если видишь в начале строки что-то вроде `(esp-idf)` или похожий префикх — окружение настроено и работает

Дальше **все команды из инструкции ниже (git clone, idf.py и т.д.) пиши именно в этом окне**, а не в обычном терминале VS Code. Сам код (config.h, .cc файлы) можно открывать и редактировать в VS Code как обычно — это просто текстовый редактор, отдельно от терминала.

## 3. Выбрать плату и язык

В открытом окне **ESP-IDF CMD** (том самом ярлыке с рабочего стола, не в VS Code терминале), перейдя в папку проекта (`cd xiaozhi-esp32` после клонирования):

```bash
idf.py set-target esp32s3
idf.py menuconfig
```

Откроется текстовое меню:
- **Xiaozhi Assistant → Board Type** → выбери **"Bread Compact WiFi + LCD (面包板)"**
- Там же можно выставить язык интерфейса, если нужен русский — проверь его наличие командой `python scripts/build.py --list-languages` до menuconfig; если ru-RU нет, оставь английский — сам голосовой диалог всё равно будет идти на русском языке (это не зависит от языка прошивки, это язык, на котором говорит LLM)

Выход из меню — Esc несколько раз, сохранить при выходе (Save).

## 5. Добавить голосовое управление мотором (MCP tool)

Это ключевой шаг. Открой `.cc` файл платы:
```
main/boards/bread-compact-wifi-lcd/bread_compact_wifi_lcd.cc
```
(имя файла может отличаться — смотри что лежит в этой папке, там будет один `.cc` файл платы)

### 5.1. Добавь пин мотора в `config.h`

В `main/boards/bread-compact-wifi-lcd/config.h` добавь строки (в любом месте после `#include`):

```c
#define MOTOR_PIN1 GPIO_NUM_2
#define MOTOR_PIN2 GPIO_NUM_3
```

### 5.2. Добавь include в `.cc` файл платы

В начало файла, где уже есть другие `#include`, добавь:

```cpp
#include "mcp_server.h"
#include <driver/gpio.h>
```

### 5.3. Настрой пин как выход

Внутри класса платы найди конструктор (строка вида `BreadCompactWifiLcdBoard() : ...`). В его теле, рядом с другими `Initialize...()` вызовами, добавь:

```cpp
void InitializeMotor() {
    gpio_config_t config = {
        .pin_bit_mask = (1ULL << MOTOR_PIN1) | (1ULL << MOTOR_PIN2),
        .mode = GPIO_MODE_OUTPUT,
        .pull_up_en = GPIO_PULLUP_DISABLE,
        .pull_down_en = GPIO_PULLDOWN_DISABLE,
        .intr_type = GPIO_INTR_DISABLE,
    };
    gpio_config(&config);
    // Стартовое состояние — мотор выключен
    gpio_set_level(MOTOR_PIN1, 1);
    gpio_set_level(MOTOR_PIN2, 0);
}
```

И вызови её в конструкторе рядом с остальными `Initialize...()`:
```cpp
InitializeMotor();
```

### 5.4. Зарегистрируй MCP-инструмент "мотор"

Там же в классе найди метод, где регистрируются существующие инструменты (обычно называется `InitializeTools()` или `InitializeIot()` — ищи по слову `AddTool` или `McpServer`). Если такого метода нет — создай и вызови из конструктора. Добавь:

```cpp
void InitializeMotorTool() {
    auto& mcp_server = McpServer::GetInstance();
    mcp_server.AddTool(
        "self.motor.control",
        "Включает или выключает мотор. Вызывай, когда пользователь просит включить, выключить, запустить или остановить мотор.",
        PropertyList({
            Property("state", kPropertyTypeBoolean)
        }),
        [this](const PropertyList& properties) -> ReturnValue {
            bool state = properties["state"].value<bool>();
            if (state) {
                gpio_set_level(MOTOR_PIN1, 0);
                gpio_set_level(MOTOR_PIN2, 1);
            } else {
                gpio_set_level(MOTOR_PIN1, 1);
                gpio_set_level(MOTOR_PIN2, 0);
            }
            return state ? "Мотор включен" : "Мотор выключен";
        });
}
```

И вызови `InitializeMotorTool();` в конструкторе после `InitializeMotor();`.

> Если точное имя класса `PropertyList`/`Property`/`ReturnValue` не совпадёт при компиляции — открой любой существующий файл платы, где уже есть `AddTool` (например `main/boards/esp-box-3/` или любой другой из `main/boards/`), и скопируй сигнатуру оттуда один в один — API может чуть отличаться версии от версии, но общий паттерн такой же.

## 6. Сборка и прошивка

```bash
idf.py build
idf.py flash monitor
```

Первая сборка идёт долго (скачивает зависимости). Дождись `Flash completed`. `monitor` покажет лог платы — Ctrl+] выход.

## 7. Первый запуск и регистрация

1. После прошивки плата поднимет точку доступа `Xiaozhi-XXXXXX` — подключись к ней с телефона/ноутбука
2. Откроется страница настройки — введи пароль от домашнего WiFi (2.4 ГГц)
3. Плата перезагрузится, подключится к интернету и голосом продиктует 6-значный код активации
4. Зайди на **https://xiaozhi.me**, зарегистрируйся, создай агента ("Add Agent")
5. В агенте нажми "Add Device", введи полученный код
6. В настройках агента выбери языковую модель (можно оставить бесплатный Qwen)

## 8. Как говорить с ботом

Заводское слово пробуждения — китайское "你好小智" (плохо ловит русскую речь как триггер). Проще всего **не полагаться на голосовое слово-будильник**, а нажимать кнопку **BOOT** на плате перед фразой — это уже встроено в прошивку (`ToggleChatState()` по клику). Нажал → сказал "включи мотор" на русском → LLM поймёт и вызовет твой инструмент.

---

## Итог

- Голос → облако Xiaozhi → LLM понимает фразу целиком (а не ключевые слова)
- LLM вызывает зарегистрированный инструмент `self.motor.control` с параметром `state: true/false`
- GPIO2 переключается, мотор (через транзистор/реле) включается/выключается
- Через ту же MCP-систему легко добавить ещё инструменты — свет, серво, датчики и т.д., просто копируя блок `AddTool`
